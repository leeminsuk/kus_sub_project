# 실제 플레이 검증 기록

2026-10-13, 로컬 프로덕션 서버에서 Playwright CLI의 독립 Chromium 세션으로 두 차례 처음부터 끝까지 실제 플레이했다. 먼저 `http://127.0.0.1:3010`의 `campus-e2e`에서 실패·재시도·저장을 확인하고, 카메라·나무 충돌·선택 발견물·로컬 폰트를 반영한 `http://127.0.0.1:3011`의 새 세션 `campus-final-e2e`에서 메인 여섯 의뢰를 다시 전부 완료했다.

## 최종 통합 빌드 재검증

최종 세션은 새 저장 상태에서 `최종 탐험가 / 열린 전공`으로 시작했다. 이전 세션의 저장 파일을 이식하거나 완료 상태를 주입하지 않았다. 실제 키보드 이동과 화면 조작만으로 **학생회관 → 도서관 → 온실 → 생명과학관 → 미래정보관 → 연못 → 중앙광장** 경로를 걸었다.

- 여섯 퀘스트를 각각 100점으로 완료하고 중앙광장에서 새 ‘이어봄’ 에필로그를 확인했다.
- 생명과학 100점·정보보안 100점, `경계를 넘는 융합 탐험가` 결과 화면과 실제 결과 PNG 다운로드가 정상 동작했다.
- 선택 발견물 `0/4`, 숨은 배지 미발견 상태에서도 엔딩이 열렸다. 선택 활동이 필수 진행을 잠그지 않는 것을 확인했다.
- 미래정보관에서 연못으로 가는 지름길에서는 `(25,24)`의 나무 앞에서 실제로 이동이 멈췄다. 왼쪽으로 약 3m 비켜 걸어 연못 NPC에게 도착했다. 나무 충돌과 정상적인 우회가 모두 동작했다.
- 엔딩 후 자유 탐험, 새로고침, 이어가기, 노트의 여섯 100점 기록 복구, 최종 JSON 백업 다운로드를 확인했다.
- 최종 브라우저 콘솔 결과는 **메시지 0, 오류 0, 경고 0**이었다. 이전 빌드의 그림자 경고가 재발하지 않았다.

최종 증거는 [결과 화면](verification-assets/final-e2e-result.png), [실제 다운로드 PNG](verification-assets/final-e2e-result-download.png), [엔딩 후 캠퍼스](verification-assets/final-e2e-festival.png), [새로고침 후 노트](verification-assets/final-e2e-restored-journal.png), [다운로드한 저장 파일](verification-assets/final-e2e-completed-save.json)이다. 저장 파일에는 여섯 완료 기록과 `endingSeen: true`, `discoveries: []`, `secretFound: false`가 남아 있다.

이 실행 중 도서관 상호작용 키 E가 자동 초점 입력칸에 한 글자 입력되는 작은 문제를 발견하여 수정했다. 수정 후 `3012` 빌드에서 입력칸이 빈 문자열로 유지되는 회귀 검증을 완료했다. 자세한 결과는 이 문서의 키보드·한글 결과 이미지 검증에 남겼다.

이하의 상세 실패·재시도 점수는 첫 검증 세션의 기록으로, 최종 재검증의 전부 100점 결과와 구분한다. 선택 발견물·이스터에그·사진 모드·모바일은 별도 검증 담당 세션의 기록을 따른다.

## 검증 방법

- 새 브라우저에서 `E2E 탐험가 / 자유전공` 여권을 만들었다.
- 이동은 실제 `W/A/S/D`, `Shift` 키 입력으로만 수행했다. NPC 근처에서 `E`로 상호작용했다.
- 좌표 이동 함수, 진행 상태 주입, 저장 파일 수정, 완료 조건 우회는 사용하지 않았다. localStorage는 실제 자동 저장 결과를 확인할 때 읽기만 했다.
- 퍼즐은 화면의 버튼·입력창·슬라이더를 조작했다. 물 슬라이더는 `Home`과 방향키로 조정하여 키보드 접근성도 확인했다.
- 각 퀘스트에서 성공 설명을 읽고 `신호를 가지고 돌아가기`를 눌러 완료를 확정했다.

## 실제 이동과 완주

게임의 기본 추천은 연못부터 시작하지만, 이번 검증에서는 학생회관부터 시작해 자유 순서 진행을 확인했다.

| 순서 | 실제 이동 목적지 | 조작·실패 검증 | 획득 점수 |
| --- | --- | --- | --- |
| 1 | 정문 → 학생회관 | 첫 피싱 메시지를 일부러 잘못 분류. 오답 해설을 확인하고 남은 4개를 맞힌 뒤 5개 모두 완료 | 80 |
| 2 | 학생회관 → 중앙도서관 | `wrong` 제출 시 실패 안내 확인. 소문자 `campus` 입력이 대문자로 정규화되어 성공 | 90 |
| 3 | 도서관 동쪽 통로 → 은행 온실 | 빈 염기 제출 거절 확인. 힌트 열기 후 여섯 버튼을 순환해 `ATGCCT` 완성 | 90 |
| 4 | 온실 → 북쪽 가로길 → 생명과학관 | 토종 들꽃·꽃벌·지렁이를 선택하고 정원 완성 | 100 |
| 5 | 생명과학관 → 미래정보관 | 외부 중계소와 공개 저장소를 거친 잘못된 경로 거절 확인. 초기화 후 단말→방화벽→인증→서버 연결 | 90 |
| 중간 | 미래정보관 → 중앙광장 | 5/6 상태에서 엔딩을 열 수 없고 `남은 신호 찾아보기`가 표시됨 | 잠금 확인 |
| 6 | 중앙광장 → 생태 연못 | 수온 20°C, pH 7, 용존 산소 7 mg/L로 조정. 3/3 조건 확인 후 완료 | 100 |
| 엔딩 | 생태 연못 → 중앙광장 | 6/6에서 축제 점등 버튼 활성화. 결과 카드 표시 후 자유 탐험 복귀 | 완료 |

첫 엔딩의 저장 결과는 생명과학 97점, 정보보안 87점이며, 칭호는 `경계를 넘는 융합 탐험가`였다. 원 점수 합계는 550/600이다. 퀘스트마다 남은 수가 갱신되고 마지막 퀘스트 완료 후 안내 대상이 중앙광장으로 바뀌었다.

## 저장·재도전·다운로드

- 엔딩 완료 직후 localStorage의 여섯 완료 기록, `trackedQuest: null`, `endingSeen: true`를 확인했다.
- 브라우저를 새로고침하자 `나의 탐험 이어가기`가 표시됐다. 이어가기 후 원래 위치와 6/6 완료 상태가 복구됐다.
- 퀘스트 노트에서 모든 최고 점수가 유지되는 것을 확인했다.
- 엔딩 뒤 도서관으로 실제 걸어가 암호를 재도전했다. 90점이 100점으로 갱신되고 `attempts: 2`가 기록됐다. 최초 완료 시각과 엔딩 상태는 유지됐다.
- `나의 결과 카드 저장`으로 실제 PNG 다운로드 이벤트를 받았고, 1200×1500 이미지의 이름·전공·칭호·점수를 시각적으로 확인했다.
- 설정의 `탐험 기록 백업`으로 JSON을 다운로드했다. 같은 파일을 정상 파일 선택창으로 불러온 뒤 `탐험 기록을 불러왔어요` 메시지와 6/6 진행 상태를 확인했다.

## 콘솔과 검증 범위

첫 `3010` 빌드의 전체 플레이에서 브라우저 콘솔 오류는 0건이었다. 최초 실행과 새로고침 시 각각 Three.js의 `PCFSoftShadowMap` 제거 및 `PCFShadowMap` 대체 경고가 1건씩 있었다. 이를 수정한 `3011` 통합 빌드에서는 위 최종 재검증에 기록한 대로 오류와 경고가 모두 0건이었다.

이 검증은 데스크톱 Chromium의 실제 WebGL·입력·저장 흐름을 대상으로 한다. 다른 브라우저, 모바일 터치, 새 선택 발견물·이스터에그·사진 기능의 테스트는 별도의 최종 검증 기록과 구분해야 한다. 위 표에 없는 동작을 검증했다고 주장하지 않는다.


## 선택 탐험·사진·작은 화면 검증

별도 새 탐험가 `탐험기록` 세션에서는 본편 퀘스트를 완료하지 않은 상태로 정문 → 호랑이 조형물 → 도서관 책 → 북서쪽 숲 → 연못 벤치까지 실제 키보드로 걸었다. 나무에 막힌 구간은 옆으로 돌아갔으며 좌표나 저장 상태를 주입하지 않았다.

- 네 발견물을 모두 직접 조사하여 여권에 기록했다. 본편 진행은 `0/6` 그대로였다.
- 호랑이 퍼즐에 잘못된 네 발자국을 입력해 재시도 안내를 확인하고, 왼쪽·오른쪽·오른쪽·왼쪽으로 숨은 배지를 얻었다. 도서관 책에서 같은 순서를 알려 주는 단서도 확인했다.
- 사진 모드에서 방향키·우클릭 드래그·휠로 카메라를 조절하고 실제 1440×900 PNG를 다운로드했다. 사진에는 HUD·NPC 이름표가 없었고 촬영 중 플레이어 위치는 유지됐다.
- JSON 백업을 다운로드했다. `{"bad":true}` 파일을 정상 파일 입력으로 올리자 안내 메시지가 표시되고 기존 네 발견물과 배지가 보존됐다.
- 390×844 뷰포트에서 가로 넘침 없이 메뉴·지도·이동 버튼·상호작용 버튼이 표시됐다. 오른쪽 이동 버튼을 포인터로 0.7초 누르고 놓자 실제 좌표가 바뀌고 이동이 멈췄다. 이는 Chromium의 작은 화면과 포인터 경로 검사이며 실제 iOS/Android 기기 검사는 아니다.
- 최종 빌드로 서버를 재시작한 뒤, 외부 호스트 요청을 차단하고 새로고침했다. 로컬 모델·폰트·화면이 로드됐고 이어가기 후 발견 `4/4` 및 `121번째 호랑이` 배지가 복구됐다. 앱 서버 자체가 필요 없는 오프라인 PWA를 의미하지 않는다.

- 정문 앞에서 지면 클릭으로 좌표가 `(0,57.8)`에서 `(2.4,53.1)`로 바뀌는 것을 확인했다. 마우스를 누른 채 방향을 바꾸는 이동도 정상 동작했다. 배경 음악 버튼의 켜기·끄기 상태 전환을 확인했으며, 이 세션 콘솔 오류·경고는 모두 0건이었다.

## 키보드·한글 결과 이미지 회귀 검증

`http://127.0.0.1:3012`의 새 Chromium 세션 `campus-keyboard-final`에서 정상 설정 UI의 파일 선택창으로 앞서 직접 완주한 JSON을 불러왔다. 저장 데이터를 수정하지 않았으며 중앙광장에서 도서관까지 실제 WASD/Shift 입력으로 걸어갔다.

- 도서관 NPC 앞에서 E를 눌러 암호 대화를 열었다. 자동 초점이 입력칸으로 이동한 뒤에도 `archive-answer.value`가 정확히 빈 문자열 `""`인 것을 읽기 전용으로 확인했다. 상호작용 키가 답안에 섞이던 문제가 재발하지 않았다.
- 같은 NPC 앞에서 HUD 설정 버튼에 초점을 두고 Enter, Space를 각각 눌렀다. 둘 다 설정 화면을 정상적으로 열었고 NPC 대화가 가로채지 않았다.
- 지도 버튼도 Enter와 Space 양쪽으로 정상 활성화됐다. Space를 누른 상태에서는 대화창이 생기지 않고, 키를 놓으면 브라우저 버튼의 기본 동작으로 지도가 열렸다. NPC 암호 창으로 바뀌지 않았다.
- 설정 → 결과 카드 다시 보기 → 나의 결과 카드 저장을 통해 새 PNG를 다운로드했다. 로컬 한글 폰트를 사용하는 1200×1500 이미지에서 이름·칭호·전공·두 점수·본문·하단 문구가 깨지거나 잘리지 않는 것을 직접 열어 확인했다.
- 이 회귀 세션의 콘솔 결과도 메시지 0, 오류 0, 경고 0이었다.

## 카메라 시야 최종 보완

탐험 중 연못 동쪽 나뭇잎과 정문 가로 간판이 캐릭터를 가리는 지점을 발견했다. 최종 구현에서는 시선과 겹치는 나무의 잎 인스턴스만 부드럽게 사라졌다가 복구된다. 정문 간판은 카메라 전용 충돌 상자로 처리하여 보행 통로를 막지 않는다. 실제 같은 지점으로 다시 이동하여 플레이어와 주변 길이 보이는 것을 확인했다. 브라우저 셰이더 오류·경고는 0건이다.

[나무 뒤의 캐릭터 시야](verification-assets/final-foliage-visibility.png), [정문 통행 중 시야](verification-assets/final-gate-visibility.png). 최종 소스에서 `npm run check`(타입 검사 + 상태 테스트 7개)와 `npm run build`가 모두 통과했다.
